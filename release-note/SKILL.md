# Release Note Generator

ソフトウェアリリースノートを自動生成するスキルです。

## 使用方法

```
/release-note --before "修正前フォルダパス" --after "修正後フォルダパス" --history "History.txtパス" --customer "顧客名" --device "装置名" --ticket "#チケット番号"
```

## 必須パラメータ

| パラメータ | 説明 | 例 |
|-----------|------|-----|
| `--before` | 修正前フォルダの絶対パス | `D:\old_version` |
| `--after` | 修正後フォルダの絶対パス | `D:\new_version` |
| `--history` | History.txtの絶対パス | `D:\project\History.txt` |
| `--customer` | 顧客名 | `UMTC蘇州` |
| `--device` | 装置名 | `G2128` |

## オプションパラメータ

| パラメータ | 説明 | デフォルト |
|-----------|------|----------|
| `--ticket` | RedMineチケット番号 | なし |
| `--version` | ソフトウェアバージョン | History.txtから自動取得 |
| `--output` | 出力ファイルの絶対パス（既存の `.xlsm` を指定すると、そのファイルを更新） | CSVのパスを自動生成 |

## 処理フロー

1. **History.txt解析**: 最新の変更履歴を抽出
2. **RedMineチケット情報取得**（--ticket指定時）: Playwrightでブラウザを開き、ログイン後にチケット情報を取得
3. **フォルダ比較**: 修正前後のファイル差分を検出
4. **お客様向けの文章にまとめる**: 「背景」「目的と適用範囲」「内容」「効果」の4項目を作成（各項目4行以内・300字以内、コード詳細は含まない）
5. **ファイル出力**: 出力先を確認し、既存の `.xlsm` には直接書き込み、それ以外はCSVを生成（詳細は「出力先の選択とXLSM更新」参照）

## 出力先の選択とXLSM更新

- `--output` またはユーザーが書き込み先として指定したパスの拡張子を確認する（大文字・小文字を区別しない）。
- 出力先が既存の `.xlsm` ファイルの場合、そのブックを読み込み、同じパスへ保存する。
- 出力先の指定がない場合、または `.csv` が指定された場合は、CSVテンプレートを使用する。
- `.xlsm` が指定されているのにファイルが存在しない、読み込めない、または保存できない場合は、原因を報告する。CSVへの切り替えや拡張子だけの変更は行わない。

### 既存XLSMへの書き込み手順

1. 更新前に同じフォルダへ日時付きのバックアップを作成する。
2. シート名、項目名、結合セルを確認し、顧客名、装置名、リリース日、概要、詳細、バージョン情報などの書き込み先を特定する。セル位置は既存様式に合わせ、特定できない項目だけユーザーに確認する。
3. 指定されたリリースノートの入力欄へ書き込む。「詳細」欄が1つの場合は、その欄に「背景」「目的と適用範囲」「内容」「効果」をまとめる。結合セルには左上セルを使用する。
4. VBAマクロ、数式、書式、結合セル、シート構成、印刷設定、および今回の対象外の内容を保持する。Excel COMなど、ブック内の機能を保持できる方法を優先する。openpyxlを使う場合は `keep_vba=True, data_only=False, keep_links=True` で読み込み、保持できない機能がある場合はExcelによる編集へ切り替える。
5. `.xlsm` 形式で保存し、再度開いて書き込み内容とブック構成、VBAの保持を確認する。マクロは実行しない。保存先、更新したシート・セル、バックアップ先、検証結果を報告する。

## 出力形式

リリースノートは以下の情報を含みます。既存のXLSMを更新する場合はその様式に合わせ、CSVの場合は付属テンプレートを使用します。

### ヘッダー情報
- ドキュメントID: `SOFT-[装置名]-RP-XXXX`
- 顧客名、装置名、リリース日、製番

### 詳細セクション（各項目最大4行）
- **【背景】**: 修正が必要となった経緯
- **【目的と適用範囲】**: 修正の目的と影響範囲
- **【内容】**: 修正内容の概要（コード詳細は含まない）
- **【効果】**: 修正による改善効果

詳細本文の見出しは、この4項目のみを上記の順序で使用します。既存ファイルを更新する場合は、詳細欄の旧本文を新しい本文で置き換えます。保存後に詳細欄を読み直し、見出しがこの4項目と一致することを確認してください。

### バージョン情報
- 制御ソフト、各種DLL、PLC等のバージョン

## 記載ルール（お客様向け文書）

1. **各項目は300字以内**でまとめる
2. **技術的詳細は一切記載しない**:
   - ❌ 変数名、関数名、クラス名
   - ❌ ファイル名、パス（対象ファイル欄以外）
   - ❌ プログラムの内部処理、アルゴリズム
   - ❌ エラーコード、例外処理の詳細
3. **お客様が理解できる表現のみ使用**:
   - ✅ 「検査時間が遅くなる問題を改善」
   - ❌ 「MI_WORKCLAMPMOVING信号のOFF待ち処理を追加」
4. **変更の「何を」「なぜ」**を重視し、「どのように」は省略
5. **効果は業務視点で記載**:
   - ✅ 「装置の安定稼働が向上します」
   - ❌ 「メモリリークが解消されます」

## 使用例

### 基本的な使用
```
/release-note --before "D:\Release\v3.19.3.5" --after "D:\Release\v3.19.3.6" --history "D:\Release\v3.19.3.6\History.txt" --customer "UMTC蘇州" --device "G2128" --ticket "#69777"
```

### 出力結果
```
リリースノート_UMTC蘇州_レーザーマーカーで非常停止発生(SOFT-G2128-RP-0280).csv
```

### 既存のXLSMファイルに書き込む場合
```
/release-note --before "D:\Release\v3.19.3.5" --after "D:\Release\v3.19.3.6" --history "D:\Release\v3.19.3.6\History.txt" --customer "UMTC蘇州" --device "G2128" --ticket "#69777" --output "D:\Release\リリースノート.xlsm"
```

指定したXLSMが存在する場合、バックアップを作成してから同じファイルを更新します。

## History.txt形式

以下の形式のHistory.txtに対応（ファイル先頭に最新エントリ）：

```
//-----------------------------------------------------------------------
GATS2120 V1.0.26.18
【CompilePC名 】
(1)
【更新日時　　】2025.12.11
【更新者　　　】Mec Hidaka
【更新区分　　】不具合対応
【更新内容　　】#72928 Nanya錦興 Gats2128 RawData異常 の修正
                非常停止したときTQAのFailre、RawDataが一時フォルダに残っていて
                運転を再開するとテスターの検査RawDataが移動できず、
                中断時に検査済みでストックする前の結果が中断前のデータになる
                不具合を修正
【対象ファイル】
                Inspect\NAutoInsp.cpp
                Inspect\YieldLogManage.cpp /.h
                Operate\FrmMainPanel.cpp
【検索ワード　】[Nanya錦興 Gats2128 RawData異常](#72928)

(2)
【更新日時　　】2025.12.19
【更新者　　　】Mec Hidaka
【更新区分　　】不具合対応(テスト用)
【更新内容　　】#73213 NANYA錦興 G2128 装置により検査時間が遅いときがある
                テスト用
                ...
【対象ファイル】
                Inspect\NAutoAlInsp3.cpp /.h
                ...
【検索ワード　】[NANYA錦興 G2128 装置により検査時間が遅いときがある テスト用](#73213)
//-----------------------------------------------------------------------
```

### History.txt解析ルール

1. **最新エントリの特定**: ファイル先頭から解析し、最も新しい【更新日時】を持つエントリを抽出
2. **複数サブエントリ対応**: (1), (2) などのサブエントリがある場合、全て含める
3. **抽出フィールド**:
   - バージョン番号: `GATS2120 Vx.x.xx.xx` から取得
   - 更新日時: 【更新日時　　】から取得
   - 更新区分: 【更新区分　　】から取得（概要生成に使用）
   - 更新内容: 【更新内容　　】から取得（詳細生成に使用）
   - 対象ファイル: 【対象ファイル】から取得（修正前後の差分確認に使用）
   - チケット番号: 更新内容内の `#xxxxx` パターンから抽出

## RedMine連携

`--ticket` パラメータでチケット番号を指定すると、Playwrightでブラウザを開いてRedMineから情報を取得します。

### 取得手順
1. ブラウザが開き、RedMineのチケットページに移動
2. ユーザーが手動でログイン
3. ログイン完了後、チケット情報を自動取得

### 取得する情報
- チケットタイトル → 概要に使用
- チケット説明 → 【背景】【目的と適用範囲】に使用
- ステータス・担当者 → 参考情報として使用

### RedMine URL
- ベースURL: https://read-sln.cloud.redmine.jp/
- チケットURL: https://read-sln.cloud.redmine.jp/issues/[チケット番号]

## 注意事項

- フォルダパスは絶対パスで指定してください
- History.txtはUTF-8またはShift-JISエンコーディングに対応
- RedMineチケット情報はPlaywright経由でブラウザログイン後に取得
